login.php
<?php
require 'comum.php';

$primeiro_acesso = ($banco->query('SELECT COUNT(*) FROM usuarios')->fetchColumn() == 0);
$erro = '';

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
  $usuario = trim($_POST['usuario'] ?? '');
  $senha = $_POST['senha'] ?? '';

  if ($primeiro_acesso) {
    if ($usuario === '' || strlen($senha) < 8) {
      $erro = 'Escolha um usuário e uma senha com 8 caracteres ou mais.';
    } else {
      $sql = $banco->prepare('INSERT INTO usuarios (usuario, senha) VALUES (?, ?)');
      $sql->execute([$usuario, password_hash($senha, PASSWORD_DEFAULT)]);
      session_regenerate_id(true);
      $_SESSION['usuario'] = $usuario;
      header('Location: painel.php');
      exit;
    }
  } else {
    $sql = $banco->prepare('SELECT senha FROM usuarios WHERE usuario = ?');
    $sql->execute([$usuario]);
    $hash = $sql->fetchColumn();
    if ($hash && password_verify($senha, $hash)) {
      session_regenerate_id(true);
      $_SESSION['usuario'] = $usuario;
      header('Location: painel.php');
      exit;
    }
    $erro = 'Usuário ou senha errados.';
  }
}

topo('Entrar');
?>
<h1><?= $primeiro_acesso ? 'Primeiro acesso: crie o administrador' : 'Entrar no painel' ?></h1>
<?php if ($erro): ?><p class="erro"><?= h($erro) ?></p><?php endif; ?>
<form method="post">
  <label>Usuário <input name="usuario" required maxlength="30"></label>
  <label>Senha <input name="senha" type="password" required></label>
  <button type="submit"><?= $primeiro_acesso ? 'Criar e entrar' : 'Entrar' ?></button>
</form>
<?php rodape(); ?>

O firewall: o porteiro do servidor

O firewall deixa entrar só pelas portas liberadas. O servidor precisa de duas: a 22 (PuTTY e WinSCP) e a 80 (site). O resto fica fechado.

A ordem importa: libere a porta 22 ANTES de ligar o firewall. Senão o PuTTY fica do lado de fora, e só se entra de novo pelo teclado do servidor.

As regras Cole

As regras do porteiro
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw show added

Ligar e testar Digite

sudo ufw enablePergunta se pode cair o SSH: y e Enter. Como a 22 está liberada, não cai
sudo ufw status numberedAs regras ativas
sudo ufw delete allow 80/tcpFecha o site. No navegador, Ctrl+F5: não abre mais
ping 192.168..10No cmd do PC: o servidor responde. Está ligado, só a porta está fechada
sudo ufw allow 80/tcpAbre de novo. Ctrl+F5: o site voltou
Na folha: explique cada linha do bloco das regras. O que quer dizer deny incoming e allow outgoing?

O backup: o site inteiro num arquivo

Se o disco do servidor queimar amanhã, o que salva o cliente é o backup. Um arquivo com o site, as fotos, o banco e a configuração Cole

Fazer o backup
sudo tar -czf ~/backup-servidor-equipe.tar.gz /var/www/html /var/www/dados /etc/nginx/sites-available/default
sudo chown $USER:$USER ~/backup-servidor-equipe.tar.gz
ls -lh ~/backup-servidor-equipe.tar.gz

O aviso Removing leading '/' é normal. Agora tire o backup do servidor:

  1. No WinSCP, lado direito, vá para a pasta de casa: /home/equipe.
  2. Arraste o backup-servidor-equipe.tar.gz para o PC (lado esquerdo), ou para o pendrive.
Na folha: o que tem dentro do backup (as três pastas e arquivos da linha do tar)? Qual o tamanho? Por que guardar fora do servidor?

A apresentação: 4 minutos por equipe

  1. 1 min · O negócio: o nicho, as páginas e as fotos, navegando pelo menu.
  2. 1 min · O cadastro ao vivo: alguém da plateia se cadastra pelo celular, no Wi-Fi da equipe.
  3. 1 min · O painel: login, o cadastro novo aparecendo, uma edição. Mostrar que sem senha não entra.
  4. 1 min · O técnico: o que a equipe fez para o cliente dormir tranquilo: firewall, atualização, backup, senha guardada em hash.

Ao terminar, desligue pelo PuTTY: sudo poweroff.
