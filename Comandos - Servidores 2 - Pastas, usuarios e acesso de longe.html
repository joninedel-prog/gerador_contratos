A revisão do servidor

Digite

Como a revisão do carro: o técnico faz isso em toda visita ao cliente. Primeiro olha como o servidor está, depois atualiza.

Como ele está?

uptimeHá quanto tempo está ligado e quanto trabalho tem
free -hMemória: total, usada e livre
df -h /Disco: tamanho, usado e quanto % já encheu
systemctl status nginxO site está rodando? Procure active (running). Sai com q
htopO painel ao vivo: processador, memória e programas. Sai com q
whoQuem está conectado agora

Atualizar

sudo apt updateBusca a lista de novidades. Ainda não instala nada
apt list --upgradableO que tem para atualizar
sudo apt upgradeInstala as atualizações. Y e Enter. Pode demorar
ls /var/run/reboot-requiredSe o arquivo existir, o servidor pede para reiniciar
sudo rebootSó se pediu. O PuTTY cai: espere 1 minuto e entre de novo
Na ficha técnica: anote o checklist da revisão com a data de hoje, a memória livre, o % do disco e quantos pacotes foram atualizados.
5

O firewall: o porteiro do servidor

O firewall deixa entrar só pelas portas que o técnico liberou. O servidor precisa de duas: a 22 (PuTTY) e a 80 (site). O resto fica fechado.

A ordem importa: libere a porta 22 ANTES de ligar o firewall. Senão o próprio PuTTY fica do lado de fora, e só se entra de novo pelo teclado do servidor.

Primeiro, as regras Cole

As regras do porteiro
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw show added
Na folha: explique cada linha. O que quer dizer deny incoming e allow outgoing?

Agora, ligar e conferir Digite

sudo ufw enablePergunta se pode cair o SSH: y e Enter. Como a 22 está liberada, não cai
sudo ufw status numberedAs regras ativas, numeradas

O teste: fechar a porta do site

sudo ufw delete allow 80/tcpFecha a porta 80. No navegador do PC, Ctrl+F5: o site não abre mais
ping 192.168..10No cmd do PC: o servidor responde. Está ligado, só a porta está fechada
sudo ufw allow 80/tcpAbre de novo. Ctrl+F5: o site voltou
sudo ufw statusConferir: 22 e 80 liberadas
Para o Encontro 3: a pasta de rede do Windows usa outra porta. A primeira coisa vai ser pedir licença ao porteiro.

Quem visitou o meu site?

Todo acesso ao site fica anotado num arquivo, o log. Deixe ele aberto na tela antes da visita das outras equipes Digite

sudo tail -f /var/log/nginx/access.logMostra o log ao vivo. Cada visita aparece na hora. Sai com Ctrl+C

Cada visita é uma linha assim:

Uma linha do log
192.168.1.104 - - [04/Dec/2026:20:41:07 -0300] "GET / HTTP/1.1" 200 2817 "-" "Mozilla/5.0 (Linux; Android 14; SM-A155M) ..."
192.168.1.104Quem visitou: o celular que entrou no Wi-Fi da equipe [04/Dec/2026:20:41:07]Dia e hora GET /O que pediu: a página inicial 200A resposta: 200 é “deu certo”. 404 é “não achei” Android 14; SM-A155MO aparelho: sistema e modelo do celular

Depois da visita, o placar: quantas vezes cada aparelho entrou Cole

O placar dos visitantes
sudo awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn
Na folha: quantos aparelhos diferentes visitaram? Algum pediu uma página que não existe (404)? O que o técnico descobre olhando um log?
