server.js · Etapa 4 · nano server.js

// Módulos que já vêm com o Node.js
const http = require('http');
const fs = require('fs');
const path = require('path');

// Porta onde o servidor vai atender
const PORTA = 3000;

// O "garçom": roda a cada pedido que chega
const servidor = http.createServer((pedido, resposta) => {
  const hora = new Date().toLocaleTimeString('pt-BR');
  console.log(`${hora} - ${pedido.socket.remoteAddress} pediu ${pedido.url}`);

  const arquivo = path.join(__dirname, 'index.html');
  fs.readFile(arquivo, (erro, conteudo) => {
    if (erro) {
      resposta.writeHead(500, { 'Content-Type': 'text/plain; charset=utf-8' });
      resposta.end('Erro: não consegui ler o index.html');
      return;
    }
    resposta.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
    resposta.end(conteudo);
  });
});

// Liga o servidor e espera pedidos de qualquer placa de rede
servidor.listen(PORTA, '0.0.0.0', () => {
  console.log(`Servidor rodando na porta ${PORTA}`);
});
⚠️ Cada ( ) { } ' ` e ; conta. Um caractere faltando e o servidor não liga.
💡 As crases ` ficam na tecla ao lado do P (com Shift no ABNT2), seguida de espaço.
✅ Checkpoint: ls mostra index.html e server.js.

Etapa 6 · teste

E se eu fechar o terminal?

No terminal do servidor, aperte:

Ctrl + C

Agora atualize o navegador (F5).

Não é possível acessar esse site
192.168.1.50 recusou a conexão.

O garçom foi embora

Com node server.js, o servidor só vive enquanto o terminal estiver aberto.

Um servidor de verdade precisa ficar ligado sozinho. Para isso existe o PM2.

7
Etapa 7

Colocar no ar com o PM2

Iniciar com um nome
$ pm2 start server.js --name meu-site
Ver o que está rodando
$ pm2 list
Ver os acessos ao vivo (Ctrl + C para sair)
$ pm2 logs meu-site

Agora o terminal fica livre e o site continua no ar.

💡 Sair dos logs com Ctrl + C não desliga o site. Só fecha a "janelinha" dos logs.
✅ Checkpoint: pm2 list mostra meu-site com status online e o site abre no outro PC.
8
Etapa 8

Alterar o site

Mudou o index.html?

$ nano index.html

Salve e aperte F5 no navegador. Pronto.

O server.js lê o arquivo a cada pedido, então a mudança aparece na hora.

Mudou o server.js?

$ nano server.js
$ pm2 restart meu-site

O código do servidor só é lido quando ele liga. Por isso precisa reiniciar.

✅ Checkpoint: mudou a cor de fundo (background) e a nova cor apareceu no outro PC.
9
Etapa 9

Ligar junto com a máquina

1. Gerar o comando de inicialização
$ pm2 startup
2. Ele mostra um comando começando com sudo — copie e rode
sudo env PATH=$PATH:/usr/bin ... pm2 startup systemd -u aluno --hp /home/aluno
3. Salvar a lista de sites rodando
$ pm2 save
4. Testar de verdade
$ sudo reboot
💡 Depois do reboot, a conexão SSH cai. Espere 1 a 2 minutos.
✅ Checkpoint: depois de reiniciar, sem fazer login, o site abre no navegador do outro PC.
Cola

Comandos do PM2

ComandoPara que serve

pm2 listMostra o que está rodando e o status
